# 测试策略

## 1. 测试分层

| 层 | 目的 | 工具 |
|---|---|---|
| 单元测试 | 模块逻辑正确性 | `pytest` |
| 属性测试 | 状态机、Lease、路径规范化 | `hypothesis` |
| 并发测试 | 真实锁竞争、幂等 | `pytest` + 多进程 |
| 集成测试 | CLI 端到端 | `pytest` + 临时目录 |
| 回放测试 | 典型授权实验场景 | 自建 fixture |
| Skill 触发测试 | 应触发 / 不应触发 | 人工 + 评测集 |
| 人力验收 | 实战效果 | 授权靶场 |

## 2. 测试原则

1. **先失败后实现**：新功能先写失败测试，再写实现
2. **测试即文档**：测试名称必须描述行为，不是实现细节
3. **不测实现细节**：优先测公共接口和状态迁移
4. **故障注入**：必须覆盖崩溃、断电、半写入、锁超时
5. **不可绕过**：安全与授权测试失败即阻断合并

## 3. 必测场景

### 授权

- 一次声明后跨会话不再重复询问
- 同一 approval key 不重复弹窗
- 不同目标、影响或过期审批不能复用
- 越界和歧义目标默认不执行
- 目标文本中的指令不改变 Scope

### 状态与并发

- 三个并发结果不丢记录
- 同一结果重放不重复
- 非法路径、哈希、schema 被拒绝
- claim 后崩溃可恢复
- 结果已写但未 ingest 可补账
- Verifier 中断可恢复

### 证据链

- confirmed 必须有 observation / reproduction / impact
- 必须有有效 artifact 和 Verifier provenance
- 同一 Worker 自我确认被拒绝
- 未处理 Cleanup 不能通过报告门禁

### 上下文与召回

- 千级节点时 context 可过滤
- 召回只返回短摘要
- Worker pack 不含无关目标
- Verifier pack 不含 Worker 成功叙事
- 包超预算时确定性裁剪并报告省略项

### 工具与数据

- 同一资产多 parser 输入只形成一个规范实体
- 低置信匹配不静默合并
- scanner warning 不能自动 confirmed
- dashboard 离线打开，图与账本一致
- 删除 SQLite / snapshot 后可从 JSONL 重建

## 4. 评测集（P4）

需建立以下回放类别：

- 成功攻击链
- 扫描误报
- 无进展 / 停滞
- 跨资产迁移
- 崩溃恢复
- 目标提示注入
- 高影响审批

每类至少一个 fixture，标注：

- 输入
- 期望状态
- 期望输出
- 期望用户交互次数
